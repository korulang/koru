# Koruc keeps build.zig.zon as a per-directory identity, not a per-build mint

`build.zig.zon` is the Zig package manager manifest `koruc` emits for Zig
dependencies. Zig 0.15 requires `.name` and `.fingerprint`, and treats the
fingerprint as a package identity, not a freshness token.

A full backend build must not dirty `git status` when no source changed. That
means the emitted `build.zig.zon` must be byte-identical across identical
inputs. This is impossible if `koruc` re-mints the fingerprint every build:
Zig's fresh fingerprint has a stable high half (the dependency set) but a
non-deterministic low half, so the file flips on every probe. It is also
impossible if the package name is derived from the input file stem, because two
entry points compiled in the same directory (`live.k`, `headed.k`) rewrite each
other's name and fingerprint.

The ruling: the manifest belongs to the output directory, not the entry point.
Its name is the directory's name, its fingerprint is the one already on disk, and
the write is skipped when bytes match. The probe build still runs so a stale
fingerprint is detected and patched, but a clean, no-change build leaves the tree
untouched.
