# A name-mangling dispatcher asserts a signature parity that no single place maintains

A call site that picks between `handler` and `handler__<variant>` by rewriting
the *name* has, without saying so, asserted that the two are interchangeable in
every other respect — arity, parameter types, comptime-ness, what is in scope
inside the body. The dispatcher is one line and looks total. **The parity it
depends on is maintained nowhere.**

In koruc the bare handler of an effect-bearing event takes
`(input, comptime __H: type)` and opens with `const tick = __H.tick;` for each
`!` arm, so the body can call arms by bare name. The variant handlers were built
by two *other* emission sites, each writing `(input) Output` from scratch, and
neither consulting `has_effect`. So an arm resolved inside the bare handler and
was an undeclared identifier inside every variant — meaning an effect arm and a
proc variant could not be combined at all, in a language whose whole pitch is
that effects and platform selection are both first-class.

The failure is invisible for a long time because **the dispatcher is right about
the common case.** A plain event's handler really is `(input) Output` on both
paths, and every variant test in the suite was a plain event. Parity held by
coincidence across the entire corpus, so the assumption never got a chance to be
wrong until a program used both features at once.

Two properties make this shape hard to see and worth naming:

**The divergence lives at the definition sites, but the error surfaces at the
call.** Nothing about `writeHandlerName` is wrong to read. You have to already
suspect the definitions to go look at them, and there were two of them, in
different files, that had drifted independently — which is the same failure
twice, not once.

**"Unselected" code is still emitted.** The variant that is never chosen is
compiled anyway, so a signature or scope defect in it fails the build on a
platform whose variant nobody picked. Dead-code elimination runs after the type
checker, never before it. This is the same lesson the `$mod.` rewrite already
taught in this exact function (370_010's first half): a variant body is real
code the moment it is written, not the moment it is selected.

The general rule: **when a dispatcher selects among definitions by mangling a
name, signature parity becomes an invariant of the emitter, and it needs one
owner.** Either every variant is generated by the same code that generates the
bare form, or something checks that they agree. Two independent writers of "the
same" signature is a divergence with a countdown on it.
