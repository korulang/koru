# tool-assay: yq in Koru

Target: a faithful yq — YAML in, YAML (or JSON) out, with a filter
language and yq's signature in-place edit (`-i`) preserving comments,
anchors, and styles. Assayed against `main @ 55ad1a0f7` (worktree
`assay-yq`, 2026-11-05) — a day after the jq assay
(`docs/assays/2026-11-05-jq.md`), which named the JSON document model
that has since landed as `std/json:dom` (`koru_std/json.dom.kz`).

yq splits into the same two problems jq did — a document model and a
filter language — plus a third jq never had: **layout preservation**.
`-i` rewrites the original file keeping comments, anchors, aliases, and
block-vs-flow style; that is a lossless syntax tree, not a DOM.

## exists (named surface + evidence)

- **stdin slurp / argv / print** — `std/io:read-stdin` (`io.kz:173`),
  `std/io:args`, `std/io:print.ln`, `read-lines` `! line` stream.
- **Document model + navigation** — `std/json:dom.parse/root/free/val/
  at/idx/len/each/render` (`koru_std/json.dom.kz`): owned `*Document`
  over a `parseFromSlice` arena, `*JsonNode` borrows, eight-variant
  typed descent, `! field`/`! item` iteration. This is the traversal
  *shape* a YAML DOM wants — the pattern is proven, the substrate
  (`std.json.Value` union, arena, `dom.*` spelling) is reusable.
- **JSON output mode** — yq `-o=json` is `dom.render` + `emit.free`,
  already green (642_005).
- **Scalar machinery** — `std/string:parse-int`, `std/num` exact
  arithmetic, `std/regex` (464 lines) — YAML's plain-scalar resolution
  (true/false/null/~/numerics) is regex-plus-conversion work over these.
- **Storage** — `std/string-map` + `! each`, `std/list` family,
  `std/array:sort`, `std/set` — an object/array model's substrate.
- **Owned node trees** — `std/tree` (`node`/`mint`/`dispose`, recursive
  free) — the lifetime discipline an in-Koru YAML tree would spell with;
  `dom`'s arena approach is already proven simpler.
- **Schema-directed JSON** — `std/json:parse`/`emit` comptime transforms
  exist for the JSON side; nothing similar for YAML (correctly —
  schemas belong to the consumer).

## missing-blocker (probed or cited absence)

- **YAML parser — zero surface.** No `koru_std/*yaml*`, no koru-libs
  package (`grep -rln yaml` over both trees: doc mentions only), no
  regression test. Everything yq is stands here. Unlike JSON, this is
  not a `parseFromSlice` call: Zig's std has **no YAML parser** (the
  JSON DOM rode `std.json.Value`+`Scanner`; there is no `std.yaml` at
  all in the vendored 0.15.2 lib), so the lexer+parser is hand-built
  surface — block indentation, flow collections, quoted/plain scalars,
  literal `|`/folded `>` blocks, document markers.
- **YAML emitter.** `dom.render` emits JSON only; yq's default output
  is block-style YAML with quoting decisions (plain vs quoted, literal
  blocks) — no surface anywhere. Same file-absence as the parser.
- **Lossless layout-preserving edit (`-i`).** yq's headline feature
  needs comments, anchors, aliases, and style choices preserved through
  a rewrite — a CST/token tree, strictly more than the Value DOM
  (`std.json.Value` carries no comment/style/tag fields; verified in
  `koru_std/json.dom.kz` type alias). Bigger than either blocker above
  and separate from them.
- **YAML node model for the full spec.** Anchors/aliases make YAML data
  a graph, not a tree; tags (`!int`, custom) and non-string keys exceed
  the `Value` union's eight variants. Core-schema YAML (no aliases,
  string keys) maps onto the existing union; full spec needs a richer
  node — the parser blocker above decides which.

## missing-but-portable (absent, workaround shape obvious)

- **Plain-scalar type resolution** — the `true/false/null/~/1.5/0x...`
  table: regex + `parse-int`/`parse-float` shapes over existing leaves.
- **Multi-document streams** — `---`/`...` framing is a line-scan over
  the slurped text (`split`/`read-lines` substrate), folded into the
  parser commission not a separate surface.
- **Expression language** — same posture as the jq assay: a
  fixed-pipeline CLI (flag-selected transform over the DOM) is stdlib;
  runtime-evaluated yq expressions are an interpreter — package work,
  deferred until the model exists.
- **YAML-as-superset ingest** — flow-style YAML is JSON-shaped; if a
  `dom`-shaped parser lands, JSON documents flow through it unchanged
  for free.

## Recommendation

Commission it, as two separable pieces. **(1) `std/yaml` parse + emit,
core schema** — block/flow collections, scalar styles + resolution,
multi-doc — over a node model that reuses the `dom` shape (arena +
borrow + `val`/`each` descent; string-keyed objects only, anchors
resolved at parse or refused). This is a *large* stdlib surface: no
`std.yaml` exists underneath, unlike the JSON DOM's free ride on
`std.json`. **(2) yq-shaped CLI + expression eval** — package work,
deferred as in the jq map. **Not commissioned:** comment/style-preserving
`-i` edit — a CST, a different and larger object than the DOM, worth
its own assay if wanted.

Cost classes: YAML parse+emit = large stdlib surface (the parser is
the whole cost; no host library underneath); CLI shell = small;
expression eval = large package work; `-i` layout preservation = CST
commission, explicitly out of this map's recommendation.
