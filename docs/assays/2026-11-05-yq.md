# tool-assay: yq in Koru (v2 — revised after judging)

Target: a faithful yq — YAML in, YAML (or JSON) out, with a filter
language and yq's signature in-place edit (`-i`) preserving comments,
anchors, and styles. Assayed against `main @ 55ad1a0f7` (worktree
`assay-yq`, 2026-11-05) — a day after the jq assay
(`docs/assays/2026-11-05-jq.md`), which named the JSON document model
that has since landed as `std/json:dom` (`koru_std/json.dom.kz`).

**v1 was falsified**: it claimed no koru-libs YAML package existed on a
case-sensitive grep that missed `~/src/koru-libs/yaml/` — tracked since
Aug 3, a libyaml lift with README, examples, and tests. That package is
a real substrate and changes the substrate question: the map is now
"build a YAML DOM on the lifted event stream (ride libyaml, the way
winnow rides pcre2) vs a dep-free parser" — the same ride-vs-build fork
the regex surface already answered.

yq splits into the same two problems jq did — a document model and a
filter language — plus a third jq never had: **layout preservation**.
`-i` rewrites the original file keeping comments, anchors, aliases, and
block-vs-flow style; that is a lossless syntax tree, not a DOM.

## exists (named surface + evidence)

- **YAML event-stream parser** — `libs/yaml` (`~/src/koru-libs/yaml/
  index.kz`, tracked since 2026-08-03): five verbs over libyaml —
  `open` (input + optional allocator → `*Parser<open!>`), `begin`
  (`*Parser<!open>` → `*Cursor<live!>`), `advance`/`finish` (consume
  the cursor per event), `close`, plus `kind` (event kind → string),
  `scalar` (event scalar bytes), `error-text`. Phantom-fused: the
  per-event `yaml_event_delete` footgun is a compile error, not a
  leak. Streaming pull events, not a tree — multi-doc, anchors,
  aliases, block+flow styles ride libyaml for free. Examples +
  tests in the package.
- **stdin slurp / argv / print** — `std/io:read-stdin` (`io.kz:173`),
  `std/io:args`, `std/io:print.ln`, `read-lines` `! line` stream.
- **Document model + navigation** — `std/json:dom.parse/root/free/val/
  at/idx/len/each/render` (`koru_std/json.dom.kz`): owned `*Document`
  over an arena, `*JsonNode` borrows, eight-variant typed descent,
  `! field`/`! item` iteration. The traversal *shape* a YAML DOM
  wants — proven a day ago, spellings reusable.
- **JSON output mode** — yq `-o=json` is `dom.render` + `emit.free`,
  green (642_005) — if a YAML parse lands into `Value`-shaped nodes.
- **Scalar machinery** — `std/string:parse-int`, `std/num` exact,
  `std/regex` — YAML plain-scalar resolution rides these.
- **Storage / trees** — `std/string-map` + `! each`, `std/list`,
  `std/array:sort`, `std/set`; `std/tree` owned-node discipline.
- **Schema-directed JSON** — `std/json:parse`/`emit` comptime
  transforms for the JSON side.

## missing-blocker (probed or cited absence)

- **YAML document model.** `libs/yaml` streams events; nothing
  assembles them into a traversable tree (no `dom`-equivalent —
  verified: the package's five verbs end at `kind`/`scalar` per-event
  reads). Building yq needs `Cursor` → node-tree assembly: either into
  `std.json.Value`-shaped nodes (core-schema YAML — string keys,
  resolved scalars, aliases expanded or refused) or a YAML-node type
  carrying tags/anchors. The assembly layer is the gap, not the
  parser.
- **YAML emitter.** `dom.render` emits JSON only; yq's default output
  is block-style YAML with quoting decisions — no emitter anywhere
  (koru_std + libs/yaml surveyed; libyaml's own emitter events are not
  lifted by the package).
- **Lossless layout-preserving edit (`-i`).** Comments, anchors,
  aliases, style choices through a rewrite — a CST/token tree, not a
  DOM (`std.json.Value` carries no comment/style/tag fields —
  verified in `json.dom.kz`; an event stream preserves even less).
  Strictly more than the DOM and separate from it.
- **Full-spec node model.** Anchors/aliases make YAML data a graph;
  tags and non-string keys exceed the eight `Value` variants. Core
  schema maps onto the existing union; full spec needs the richer
  node — decided by whichever DOM path is taken.

## missing-but-portable (absent, workaround shape obvious)

- **Plain-scalar type resolution** — the `true/false/null/~/1.5`
  table: regex + `parse-int`/`parse-float` over existing leaves.
- **Multi-document streams** — libyaml's event stream already carries
  document-start/end events; folding them into a `dom.*`-shaped
  surface is package work, not new machinery.
- **Expression language** — same posture as jq: a fixed-pipeline CLI
  is stdlib; runtime-evaluated yq expressions are an interpreter —
  package work, deferred until the model exists.
- **`-o=json` round-trip** — free once a YAML→`Value` DOM exists:
  `dom.render` already serializes that node type.

## Recommendation

Commission the DOM **on the lifted event stream**: a
`libs/yaml`-backed (or `std/yaml` re-exporting it) assembly tor —
`Cursor` events → `*Document`/`JsonNode`-shaped tree — plus a block
-YAML emitter. The ride-libyaml path is the measured-cheap one: the
parser, obligations, and multi-doc handling are already lifted and
tested (the winnow/pcre2 precedent); a dep-free hand parser buys only
dependency freedom and is the larger work. The DOM tor surface mirrors
`dom.*` spellings — same navigation contract, YAML source. **Not
commissioned:** `-i` layout-preserving edit — a CST, a different and
larger object, worth its own assay if wanted.

Cost classes: DOM-over-events assembly = medium package/stdlib work
(parser already lifted; the tree + obligations + `Value`-bridge is
the work); emitter = medium stdlib; expression eval = large package
work, deferred; `-i` CST = its own commission, out of scope here.
